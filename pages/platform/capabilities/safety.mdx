# Safety and Crisis Response

Comprehensive crisis detection, provider alerting, and HIPAA-compliant audit trail.

## Crisis Screening Protocol

### Onboarding Flow
- Endpoint: /api/onboarding/crisis-screening
- Detection: Suicidal ideation, self-harm thoughts, immediate danger
- Risk Levels: none, low, moderate, high, immediate

### Features
- 988 Resources: Suicide and Crisis Lifeline integration
- Safety Plan Generation: Guided safety planning
- Prevents Onboarding: If immediate risk detected, requires crisis resources first
- Documentation: Risk level stored for provider review

## Distress Classifier

### Multi-Context Analysis
Text analyzed from:
- Journal entries
- Assessment free-text responses
- Forum posts
- Reflection prompts
- Checkins

### Classification Thresholds
- None (less than 60% confidence): No intervention
- Mild (60-85% confidence): Gentle check-in prompt
- Crisis (85% confidence or higher): Modal + provider alert + 988 resources

### Zero-Knowledge Architecture
Privacy Guarantees:
- Input text never stored
- Input text never logged
- Only metadata persisted: classification level, confidence, context, timestamp
- No PHI in audit logs
- Encrypted in transit (TLS 1.2+)
- BAA-ready for HIPAA compliance

### Fail-Safe
- Timeout: If classifier unavailable (over 3s timeout), returns 'none'
- User Experience: Unaffected by service outages
- Degraded Safety: Fallback to keyword gate and PHQ-9 Item 9 gate

## PHQ-9 Item 9 Gate

### Independent Safety Layer
- Item 9: "Thoughts that you would be better off dead or of hurting yourself"
- Scoring: 0 (Not at all) to 3 (Nearly every day)
- Threshold: Response of 2 or higher triggers crisis modal
- Independence: Works separately from ML classifier (redundant safety)

### Action Triggers
When threshold is met:
- Crisis modal appears immediately
- 988 hotline displayed prominently
- Crisis Text Line (text HOME to 741741)
- Emergency services (911)
- Provider alert sent (if patient has provider)

### Coverage
- Onboarding: During initial PHQ-9 assessment
- Ongoing: Every PHQ-9 completion throughout platform use
- Real-Time: Immediate response, no delay

## Provider Alert System

### Crisis Alerts
When distress classifier detects crisis-level distress or PHQ-9 Item 9 threshold is met:
- Immediate email alert to assigned provider
- Alert stored in providerAlert table
- Alert visible in provider dashboard
- Alert includes:
  - Patient name
  - Alert type (distress or suicidal ideation)
  - Trigger context (journal, assessment, forum)
  - Timestamp
  - Severity level
  - Action taken (crisis modal shown, resources provided)

Crisis alerts require provider acknowledgment. Providers can:
- Mark as reviewed
- Add notes
- Schedule follow-up
- Escalate to emergency services if needed

### Alert Resolution
- Providers must acknowledge crisis alerts
- Notes field for documentation
- Resolution timestamp tracked
- Audit trail maintained for HIPAA compliance

### Alert Types
- Crisis distress detected
- Suicidal ideation (PHQ-9 Item 9)
- Severe symptom worsening
- Treatment plan non-adherence

## Wellness Alerts

### Alert Generation
Providers receive alerts when:
- Patient symptom scores worsen significantly (20+ point drop in wellness dimension)
- Patient disengages (no logins for 7+ days after active period)
- Assessment scores increase (PHQ-9 or GAD-7 jump by 5+ points)
- Treatment goals not progressing (no course progress in 14 days)

These are lower-priority alerts compared to crisis alerts. Providers can:
- Review patient dashboard
- Send check-in message
- Adjust assigned courses
- Schedule session
- Mark as reviewed

### Smart Recommendations
Alerts include AI-generated recommendations based on:
- Patient engagement patterns
- Assessment score trends
- Course progress data
- Provider notes history

## Audit Trail

### HIPAA-Compliant Logging
All safety-related actions logged:
- Crisis screening results
- Distress classifier outputs (metadata only, no input text)
- PHQ-9 Item 9 responses
- Crisis modal displays
- Provider alerts sent
- Provider alert acknowledgments
- Patient crisis resource access

Audit log includes:
- Timestamp
- User ID
- Action type
- Metadata (severity, confidence, context)
- IP address (anonymized after 30 days)

### Access Controls
- Audit logs visible to admins only
- Providers can view logs for their assigned patients
- Patients cannot view audit logs (privacy protection)

## Keyword Gate (Optimization School)

### Lightweight Safety Layer
For optimization school content (lower clinical risk), keyword-based safety layer:
- Scans user input for crisis keywords
- Lower computational overhead than ML classifier
- Sufficient for preventive/optimization content

### Trigger Keywords
Crisis keywords include:
- suicide, kill myself, end it all
- self-harm, cutting, hurt myself
- no reason to live, better off dead

### Action
When keyword detected:
- Crisis resource modal shown
- No provider alert (optimization students may not have providers)
- Event logged for monitoring
- User can dismiss and continue

## Forum Moderation Safety

### AI Pre-Publication Scan
Before post publication:
- Distress classifier analyzes post content
- If crisis-level distress detected, user sees warning
- User can choose to edit or publish anyway
- If published, provider alert sent (if user has provider)

### Post-Publication Monitoring
- Distress Classifier: Runs on all published posts
- Crisis Detection: Same 85% threshold
- Provider Alerts: If user has provider
- User Support: Crisis modal for post author
